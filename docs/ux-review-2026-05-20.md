# CSH Ticketing — UX Review

**Date:** 2026-05-20
**Reviewer:** Claude (Opus 4.7) walkthrough with Prithviraj Hulgur
**Method:** Live Playwright session, page-by-page critique against system-design and UX heuristics

> **Context — app is in development.** Seed/test data is intentionally present (e.g. `[Seed]` prefix, dev ticket IDs, "IT BOT" user). Findings tagged "seed leak" are pre-prod cleanup, not bugs. Raw enum strings (`IN_PROGRESS`, `REOPENED`) and other implementation details bleeding into UI *are* still flagged as bugs — those are independent of seed data.

## 1. Dashboard (`/dashboard`)

### Working
- Three-column intent (nav / overview / vitals) is conventional and scannable.
- Sidebar grouped into navigation → teams → primary action is findable.
- Time-range selector placed correctly with the metrics it scopes.

### Issues

**1.1 Navigation leak — Admin sub-sidebar visible on Dashboard.** A secondary "Administration" sidebar is rendered next to the primary nav even though the route is `/dashboard`. Sub-navs should only mount when their parent section is active.

**1.2 Placeholder brand.** Top-left reads "T Ticket" — looks like a dev placeholder, not a brand. Replace with the real product/org mark.

**1.3 Duplicated KPIs across three regions.**
- Main column: Total Open (8), Total Transfers (3), Reopen Rate (17%).
- Right rail Executive Vitals: Open (8), Closed (6), Total (14), Active agents (4), Transfers (3).
- Team Summary table: same Open counts again per team.
The same numbers appearing in three places is noise; pick one canonical home per metric.

**1.4 Hierarchy fights itself.**
- Only "Total Open" is rendered as an inverted dark card — implying it's *the* hero metric — but it is also repeated in the right rail and the team table, diluting the emphasis.
- "17%" reopen rate is colored red without a threshold legend. Color is doing semantic work with no key.

**1.5 Platform Activity chart is mostly empty.** 30 days of flatline plus one bump (05-04 → 05-06). At this data volume a sparkline + "last spike: 05-05" would communicate more honestly than a 600px chart.

**1.6 Sidebar density.** Nine saved-filter buttons under "All Tickets" are always expanded with live counts (Assigned / Watching / Mentions / P1 today / Awaiting reply / Breach risk / Unassigned / Resolved this week / Reopened). These compete for attention on *every* page. Collapse by default, or move them into the All Tickets page header as chips.

**1.7 Two competing page titles.** Header says "Dashboard / Quick view of your ticket activity." Body says "Platform Overview / Cross-team performance and business metrics." Pick one.

**1.8 Top Performers leaderboard appears inverted.** "#1 Alex Park — 193.1h FRT" means a first-response time of ~8 days, which would be worst, not best. Either the ranking sorts ascending on the wrong field or the label should be "Slowest FRT". Currently the leaderboard misinforms.

**1.9 SLA Compliance chart shows Breached > Met but is whisper-quiet.** If the majority of tickets are breaching SLA, the dashboard should surface that with a banner or red callout, not bury it in a right-rail card with no commentary.

**1.10 Single-letter team labels.** "AI", "HR" in the Teams group have no tooltip or fuller name. New users can't disambiguate.

**1.11 Global controls in the wrong place.** "Switch to dark mode" and "Collapse sidebar" sit at the bottom of a long sidebar. These are app-level chrome and belong near the avatar in the header utility area.

**1.12 Active-state hierarchy reversed.** The active "Dashboard" nav row is more subtly styled than the "+ New Ticket" CTA. Active state should be the dominant visual on the nav.

### One-line verdict
*The data is present but the screen doesn't decide what matters — KPIs duplicate, color is decorative not semantic, and the most alarming signal (SLA breach) is the quietest pixel on screen.*

### Interactive findings (click-through pass)

**1.I-a [BUG] No loading state.** Initial render shows "0 / 0 / 0%" for every KPI, empty charts, no Top Performers — then data hydrates after ~2 seconds. No skeletons, no shimmer, no spinner. First-time users will believe the system is empty before realising they're looking at a loading placeholder.

**1.I-b [BUG] KPI cards are not clickable.** `Total Open`, `Total Transfers`, `Reopen Rate` and every Executive Vitals row render as plain `<div>` — no `cursor: pointer`, no `onclick`, no `role="button"`, no `tabindex`. A dashboard's whole job is drill-down: "I see 8 open, take me to them." Currently the user must manually walk to All Tickets and filter. Wrap each KPI as a `<Link>` to the equivalent `/tickets?...` query.

**1.I-c [BUG] Time range only partially wired.** Switching from "Last 30 days" → "Last 7 days" changed *only* the Transfers value (3 → 0). Closed Tickets (6), Total Requests (14), Active Agents (4), and the Platform Activity chart all stayed identical. Either the time range is meant to scope everything (and most cards ignore it) or only Transfers (and the UI implies otherwise). Either way the user can't trust what they see.

**1.I-d Time-range options are thin.** Only 3 / 7 / 30 days. No "Today", "Yesterday", "Quarter to date", "Custom range." For an exec-overview screen that's underpowered.

**1.I-e Native `<select>` for time range, unthemed.** Stands out as a light-on-dark element in dark mode. Use a styled custom dropdown matching the rest of the UI.

**1.I-f Dark mode kills hero emphasis.** In light mode, `Total Open` is an inverted dark card — making it the visual headline. In dark mode it loses the contrast trick and is indistinguishable from the other two KPIs. The hierarchy disappears.

**1.I-g [BUG] Admin sub-sidebar mounted on every route.** Verified via DOM snapshot: the Administration nav (SLA, Routing, Automation, Custom Fields, Audit, Categories, Reports, AI Pipeline Debug) is in the document on `/dashboard`, `/submit`, etc. — just CSS-hidden. Pollutes accessibility tree, search, and tab order. Conditionally render.

**1.I-h Sidebar visual stability.** Across `/dashboard` → `/submit` → back to `/dashboard`, the sidebar appears to shift items vertically (Dashboard nav not always at the same Y). Worth verifying on slower hardware; perceived layout instability erodes trust.

**1.I-i [WIN] Command palette (⌘K) is the strongest UX on the app.** Linear/Slack-style — Actions (Create New Ticket, Alt+N) + Pages, keyboard hints visible, decent live search. Tickets returned with title, ID, status, team, priority badge. Keep building on this.

**1.I-j [BUG] Search result leaks dev artifacts.**
- `[Seed]` prefix from seed data appears in titles.
- Status enums render as raw DB values: `REOPENED`, `IN_PROGRESS`. Use human strings ("Reopened", "In Progress").
- No date / age on results — for a help-desk "last updated 3h ago" is one of the highest-value cues; omit it and users default to opening every result to check freshness.

**1.I-k Notifications panel — half-done.**
- Date is `5/1/2026` — locale-ambiguous (US: May 1; ISO/EU expectation: Jan 5). Use a robust format (`May 1, 2026`) or relative ("yesterday").
- "New reply on ticket" doesn't preview *who* replied or *what* — that's the entire reason to read a notification.
- Raw ticket ID `IS_20260430_010` leaks. Show ticket title (or both).
- No grouping / filtering tabs (mentions vs assignments vs SLA).

**1.I-l Account menu is sparse.** Only "Sign out." No My Profile, Preferences, Notification settings, API tokens, Help, Keyboard shortcuts. Email is rendered twice (once below the name, once in the table). Job Title, Department, Team are `—` placeholders with no way to populate from here.

**1.I-m Sidebar collapse works well.** Icons + active state read clearly when collapsed; main content gets meaningfully more horizontal room. Nit: the "+ New Ticket" CTA shrinks to a tiny purple square with no label, losing its emphasis. Consider keeping the label visible or replacing the square with a more recognizable + icon at its current size.

**1.I-n Sidebar Teams group has color dots but no role indicator.** "AI / HR / IT Service Desk / Medicaid Pending / White Gloves" each get a small color square. Color carries the entire identity — there's no icon distinguishing them. Colorblind users get a bullet list with no semantic.

## 2. AI Submit (`/submit`)

### Working
- Single centered "How can we help?" input is the right primary affordance for an AI-routed system.
- Four example chips set expectations on input quality and length.
- Attachment + send icons in-textarea match modern chat conventions.
- Admin sub-sidebar correctly hidden here (the dashboard leak is not universal).

### Issues

**2.1 Two competing "create ticket" entry points.** Sidebar still shows "+ New Ticket" while on `/submit`. Either hide the CTA on this route or merge the two flows — currently it implies two different submission paths with no explanation.

**2.2 No escape hatch to a classic form.** Users in HR / Medicaid contexts often need to set requester, priority, attachments first. Provide a "Prefer a form?" link so AI-routing is the default but not the only path.

**2.3 Example chips have ambiguous behavior.** Unclear whether clicking fills the textarea, auto-submits, or opens a sample. Add a hover hint or explicit "Use this" action.

**2.4 No "what happens next" preview.** A two-line reassurance ("We'll classify, route, and let you review before filing") would de-mystify the AI step.

**2.5 No human-in-the-loop signal.** The page should foreshadow that the user gets to review AI classification before the ticket is created. Trust is built before submit, not after.

**2.6 Two-thirds of the viewport is empty.** Candidates to fill it usefully: recent submissions by this user, common self-service deflections, or a small "AI routing healthy · avg 4s" status pill.

**2.7 Send button low-contrast.** Purple paper-plane on lavender background reads as disabled. Move to a solid accent fill once text is present.

**2.8 No input guidance.** No character counter or hint ("Include the error message and what you were doing"). Quality of the AI output is gated on input quality.

**2.9 Form semantics.** Heading "How can we help?" + body copy + textarea aren't bound in a labeled `<form>` with `aria-describedby`. Screen reader pass is disjointed.

**2.10 Responsive check pending.** 2×2 example grid likely degrades on narrow viewports — flag for later.

### One-line verdict
*The single-box idea is right, but the page over-trusts the user to know what the box does — add a "here's what AI will do," a way to use the examples, and an escape hatch to a classic form.*

### Interactive findings (click-through pass)

**2.I-a [BUG] Example chip silently overwrites typed input.** I typed "My VPN keeps disconnecting…" then clicked the PTO example chip — my entire message was replaced with no warning, no undo. This is a data-loss bug, especially since the chips are large and easy to brush. Fix options: (a) confirm before overwriting non-empty input, (b) append instead of replace, (c) treat the chip as a tooltip preview and require a separate "Use this" button to commit.

**2.I-b [BUG] Attach button is a dead feature in production.** Labeled "Attach file (coming soon)" — clicking does nothing (no toast, no modal, no error). Hovering produces no tooltip; the "(coming soon)" string lives only in the aria-label, invisible to sighted users. A half-built feature that looks active is worse than no feature: pull it from the page until it works, or visually disable it (greyed out + tooltip "Attachments coming soon").

**2.I-c [RETRACTION] Send button activation works.** Original review said send looked disabled — incorrect. Send is actually disabled in DOM until text is present, then flips to solid purple. The default-state contrast issue is real but milder than I claimed.

**2.I-d [BUG] Admin sub-sidebar is in the DOM on every page.** Visually it's hidden by CSS on `/submit`, but the entire "Administration" navigation tree (SLA Policies, Routing Rules, Automation, Custom Fields, Audit Logs, Categories, Reports, AI Pipeline Debug) is still mounted on every route. This bloats the accessibility tree (screen readers will read it), adds noise to search and tab order, and risks tabIndex leaks. Conditionally render rather than visually hide.

**2.I-e Sidebar shifts when route changes.** On `/dashboard` the nav starts with "Dashboard" at the top of the visible area; on `/submit` "AI Submit" sits in the same vertical position with no Dashboard above. Hard to tell from screenshots alone whether this is a scroll, a layout shift, or items being conditionally hidden — but the visual instability is jarring. Worth investigating.

## 3. All Tickets / Queue (`/tickets`)

### Working
- Clean queue table with bulk-select, dense rows, colour-coded priority/status badges.
- Toolbar gives Open / Resolved tabs, search, Assignee + Priority + Sort dropdowns, **Advanced** filter modal, **Save view**.
- Advanced panel is more complete than first appears: Status (9), Priority (4), Team, Assignee, Requester, **SLA Status** (On track / At risk / Breached), **Created/Updated/Due date ranges**, Contains text search.
- Master-detail layout on row click (list shrinks left, detail centers, side panel right) is a strong pattern.
- URL state preserved when navigating *into* the page (`/tickets?scope=assigned&statusGroup=open` works from sidebar).

### Issues

**3.1 [BUG] Row click does not update the URL.** Clicking a ticket opens master-detail in-place, but URL stays `/tickets`. Consequences: cannot bookmark a ticket, cannot share a link to a ticket, refresh loses the open ticket, browser back/forward broken. The canonical route should be `/tickets/:id` (or `/tickets?id=…`) synced from row selection. This is the single biggest issue on this page.

**3.2 Three different names for the same screen.** Sidebar = "All Tickets", URL = `/tickets`, page header = "Queue". Pick one term and use it everywhere.

**3.3 Status taxonomy mixes two facets.** The 9 statuses are: `New, Triaged, Assigned, In Progress, Waiting on Requester, Waiting on Vendor, Resolved, Closed, Reopened`. That blends lifecycle (`New → Triaged → Assigned → In Progress → Resolved → Closed`) with **waiting reasons** (`Waiting on Requester`, `Waiting on Vendor`) and **lifecycle markers** (`Reopened`). Better model: Status (5–6 lifecycle states) + a separate Waiting Reason field + a Reopened flag/counter. Same data, cleaner filters.

**3.4 "Assigned" as a Status is redundant.** Every row except "Waiting on Requester" / "Reopened" / "In Progress" shows Status = `Assigned`, while the next column already shows the assignee. The Status column carries no extra information for those rows. Drop "Assigned" as a status, or replace with a more useful triaged/queued distinction.

**3.5 Sort labels are ambiguous.** Options: `Sort: Newest / Oldest / Created / Created (oldest) / Completed`. What is "Newest" sorting on if "Created" is a separate option? Rename to: *Last updated (newest)*, *Last updated (oldest)*, *Created (newest)*, *Created (oldest)*, *Recently resolved*.

**3.6 No Priority sort.** For a help-desk queue this is the #1 sort. Currently I can filter by priority but can't sort by it.

**3.7 No SLA / age column in the table.** "Waiting on Requester" without "for 6 days" is missing the most important context. Add an SLA / age column (or surface the breach state as a row-level icon).

**3.8 Filter discoverability — popover scrolls below fold.** SLA Status, Date range filters, and Contains search are hidden below the fold of the Advanced popover. Many users will assume the panel only has Status/Priority. Either make the panel taller, two-column, or sticky-section.

**3.9 No Category / Type / Tag filter.** No way to filter by Incident vs Request, or by tag.

**3.10 No AND/OR/NOT logic.** Filters are all AND-only. "P1 OR P2 AND not assigned to me" is a common query and currently unbuildable.

**3.11 Bulk-select checkboxes with no bulk-action bar visible.** Every row has a checkbox but I see no sticky action bar offering Assign / Status change / Transfer / Bulk close. Either wire those actions or remove the checkboxes.

**3.12 No saved-filter management UI.** "Save view" implies you can persist a filter set, but there's no visible list of saved views, no rename, no delete, no share-with-team. Without management UI the feature is half-built.

**3.13 In-page filter chips missing.** The sidebar has 9 always-on filter shortcuts (Assigned to me, P1 today, Awaiting reply, …). Those belong here as chips above the table, scoped to the All Tickets page — not as global persistent sidebar entries. That single change removes the biggest source of sidebar density.

**3.14 Active scope not shown in the heading.** When I arrive from sidebar "Assigned to me", the heading still just says "Queue · 8 open tickets" — I lose the awareness that I'm looking at a filtered slice. Header should reflect active scope: "Assigned to me · Open · 3 tickets".

**3.15 ID column is heavy.** `IS_20260430_010` consumes a lot of width and isn't human-readable. Either use a short auto-increment (`#1284`), move the full ID to hover/tooltip, or compress (`IS-0430-010`).

**3.16 No grouping toggle.** Cannot group by Assignee / Priority / Status / Team / Day. For triage workflows, grouping is essential.

**3.17 Density toggle missing.** Rows are ~64px tall — fine for casual use, but managers reviewing 50+ tickets need a compact mode (≈36px) to scan.

**3.18 Date format inconsistency.** "Apr 30, 2026" in the list vs `04-30` on Dashboard chart vs `5/1/2026` in notifications — three formats in three places.

### One-line verdict
*The queue is well-equipped on filters and layout, but a missing URL sync on row click, ambiguous sort labels, and a status taxonomy that mixes two facets mean the page underperforms the data behind it.*

### Retractions (after operator feedback)

**3.R-1 "Three names for the same screen" — RETRACT.** The top header text ("Queue" / ticket ID / etc.) is the active **tab label** in a Chrome-style tab system, not a page title. Sidebar "All Tickets", URL `/tickets`, and tab "Queue" each address a different concept (nav label / route / tab content). No naming bug; remove finding 3.2.

**3.R-2 "URL doesn't sync on row click" — soften.** Per-ticket URLs exist at `/tickets/:uuid` and right-click → "Open in new tab" works. The detail page exposes a **Copy ticket link** button (top-right of title) that puts the canonical URL in the clipboard. So link-sharing is supported. The remaining UX gap is narrower: left-click in master-detail mode doesn't push browser history, so browser back/refresh still don't address the open ticket. Worth fixing but not a sharing blocker.

## 4. Ticket Detail (`/tickets/:uuid`)

### Working
- **Three-pane layout** (master list / detail / metadata) is industry-standard and well-executed.
- **AI Classification card** with confidence score (95) on the right rail — transparent.
- **Conversation thread** has date dividers, mentions support (`@Labor Monitor`), avatar/initials, public/internal toggle in composer.
- **Reply composer** has a real rich-text toolbar: bold, italic, lists, code block, link, **Insert template** (canned response support is a real productivity feature).
- **SLA Tracking** card splits **First Response** (Met) and **Resolution** (Paused) — explicit and honest.
- **Status / Assignee / Department** are inline-editable via dropdowns in the side panel.
- **Followers** shown as avatar row with **Unfollow** action.
- **Status History** collapsed with count `(4)` — good progressive disclosure default.
- **Copy ticket link** button — confirmed in DOM and verified working (clipboard contains canonical URL).
- **Channel/source badge** ("Portal") in top tab strip — useful triage context.

### Issues

**4.1 [BUG] Priority and Category are read-only.** Status, Assignee, Department render as `<button>` (open a picker). Priority and Category render as plain text — verified via DOM inspection. Priority change is one of the most common triage actions; making it un-editable from the side panel forces a workflow detour. Same for Category.

**4.2 [BUG] Copy link gives no confirmation.** Clicking "Copy ticket link" writes to clipboard silently — no toast, no aria-live announcement, no checkmark. Standard pattern: show a 2s "Link copied" toast or temporarily swap the icon for a checkmark.

**4.3 [BUG/UX] Copied URL uses opaque UUID.** Clipboard contains `/tickets/7fe5d219-26da-4722-928a-00264943563c`. The ticket has a memorable human ID `IS_20260430_010`. UUID URLs aren't recognizable in Slack/email/Jira links. Make the canonical share URL `/tickets/IS_20260430_010` (keep `/tickets/:uuid` as a redirect for back-compat).

**4.4 ["You" vs actual name] in own conversation messages.** The current user's messages alternate between "You" and "Prithviraj Hulgur" depending on which row in the thread. Pick one: either "You" everywhere viewed by self, or always full name. Mixing them is confusing.

**4.5 Status label casing inconsistent across views.** Side panel: `Waiting On Requester` (all words capitalized). Advanced filters earlier: `Waiting on Requester` (lowercase "on"). Detail-page top tab: `Waiting On Requester`. Pick a single casing.

**4.6 "Portal" channel badge is unlabeled.** A new user won't know whether "Portal" means web-form, email-ingested, API-created, etc. Tooltip or in-text hint ("Source: Portal").

**4.7 Followers section is mislabeled.** Section title is **Actions** but the visible content is a follower/watcher avatar row + Unfollow button. Move followers to a "Watchers" section and reserve "Actions" for one-click verbs (Reassign, Transfer to Team, Close, Resolve).

**4.8 Missing one-click action toolbar.** Common triage actions (Reassign, Transfer to Team, Mark Resolved, Close) require diving into right-rail dropdowns. A row of one-click action buttons at the top of the detail (or above the composer) would shave seconds off every ticket touch.

**4.9 AI Classification has no "override / reclassify" affordance.** Score is 95 (no `%` suffix). If the AI is wrong, where do I correct it? No visible way to override, see alternatives, or see model reasoning. The page builds trust then leaves no escape valve.

**4.10 Composer keyboard shortcuts undocumented.** No "Cmd+Enter to send" hint, no Esc to cancel, no `/` for slash commands. Power users will try these and either nothing happens or worse — Enter inserts a newline when they expected to send.

**4.11 Duplicate file-attach controls.** Composer footer has both a paperclip "Attach file" button *and* a "Choose File" button. One is enough.

**4.12 Public vs Internal note: not visually differentiated in the thread.** The composer has a toggle for Public/Internal, but in the rendered thread above, all messages are styled identically. Internal notes should have a distinct tint or "Internal" badge — otherwise an agent might miss that a private note is private (or vice versa).

**4.13 Reference field duplicates ID.** Right-rail "Information" includes `Reference: IS_20260430_010`. That's the same ID shown in the top tab. Either drop the row or rename it to convey what's different (e.g. "External ticket ID" or "Original email subject").

**4.14 Date formats still inconsistent.** Conversation: "May 1, 4:09 PM". Information panel: "Apr 30, 2026". List: "14d". SLA: "May 1, 2026". Same page, four formats.

**4.15 SLA "Paused, May 5, 2026" is ambiguous.** Is the SLA paused *since* May 5, or *until* May 5? Spell out: "Paused since May 5".

**4.16 No "Jump to next/previous ticket" shortcut.** With a list-detail layout the highest-value keyboard shortcut is J/K (or arrows) to walk the queue without taking hands off keyboard. Missing.

**4.17 Status History collapsed count says "(4)" but doesn't hint at the last change.** When collapsed, surface the most recent transition: "Last change: → Waiting on Requester · 5d ago".

**4.18 No "Linked / Related tickets" section.** Duplicates, parent/child, "see also" are core ticketing workflows and not represented.

**4.19 No requester context.** "Prithviraj Hulgur" — opens the same question every assignee asks: how many other tickets does this person have open? When did they last contact us? A small "View requester · 7 tickets · 2 open" link would save time.

**4.20 Send button is `[disabled]` until text is typed.** Same minor low-contrast issue as AI Submit when empty. Reasonable but worth a darker disabled state for clarity.

### One-line verdict
*The detail page is the most mature surface in the app — strong layout, AI confidence shown, SLA visible, real rich-text composer — but small things (read-only priority, UUID share URLs, undocumented shortcuts) keep it short of a polished triage cockpit.*

### Retractions (after operator feedback)

**4.R-1 Finding 4.2 "Copy link is silent" — RETRACT.** Operator confirmed a "✓ Link copied to clipboard" toast does appear (screenshot supplied). My evaluation likely fired after dismissal or my selector missed the toast's class. The feature works as expected.

**4.R-2 Finding 4.4 "'You' vs 'Prithviraj Hulgur' mix" — RETRACT.** Intentional and correct: **You** = the ticket owner (currently logged-in agent), **Prithviraj Hulgur** = the submitter/requester. Two roles in one conversation, each labeled by role. Good UX, not a bug.

## 5. My Tickets (`/tickets?scope=created`)

Same component as the queue, filtered to tickets where the current user is the *requester*. Sidebar entry "My Tickets" links here.

### Working
- Reuses the queue UI — consistent, no separate page to maintain.
- Sidebar entry highlights when active.
- URL is scope-encoded (`?scope=created`), shareable, bookmarkable.

### Issues

**5.1 [BUG] Pluralization.** "1 tickets" — should be "1 ticket".

**5.2 Label is ambiguous.** "My Tickets" reasonably reads as either *submitted by me* or *assigned to me*. The implementation is *submitted*. Rename to "Submitted by me" — pairs cleanly with the existing "Assigned to me" sidebar filter.

**5.3 No scope confirmation in the page body.** No H1 / chip / status string showing "Submitted by me · 1 ticket". The only signal is the highlighted sidebar item.

**5.4 Queue tab badge "1" is misleading.** Tab strip shows "Queue 1" but the Queue is 8 open tickets. The "1" appears to track something else (page result count? unread changes?). Either clarify or remove.

**5.5 [BUG] `/my-tickets` direct URL → 404 with stale "Dashboard" header.** Intuitive guess, breaks badly. Either redirect `/my-tickets` → `/tickets?scope=created`, or ensure the 404 page has its own header, not the dashboard's.

**5.6 Pagination footer overkill for 1 row.** "Showing 1 to 1 of 1 results / Rows 50 / Previous / 1 / Next" — hide when total ≤ page size.

**5.7 Sidebar "My Tickets" has no count badge** while every sub-filter under "All Tickets" has one. Consistency.

**5.8 No combined "My Activity" view.** Submitted + Assigned + Watching + Mentioned in one fused stream would match how users mentally model "my stuff" better than four separate scopes.

### One-line verdict
*Reusing the queue UI is the right architectural call; the page just needs a real heading, accurate pluralization, and a sharper label so users know what scope they're looking at.*

## 6. Triage Board (`/triage`)

Kanban-style board with 7 columns: New / Triaged / Assigned / In Progress / Waiting on Requester / Waiting on Vendor / Reopened. (Resolved & Closed correctly excluded.)

### Working
- Clear page title with scope: "Triage Board (8 tickets)".
- Cards carry rich metadata: ID, priority, SLA badge, subject, requester, team, assignee, category, channel, inline status dropdown, updated date.
- **Inline status dropdown on each card** — change status without opening the ticket. Useful.
- "Paused" SLA badge correctly appears on Waiting on Requester cards (SLA clock paused) — honest signal.
- Column counts in headers.
- Sidebar search + team filter scoped to the board.

### Issues

**6.1 Seven columns is too many.** Only 4 fit at 1440px; the right half (Waiting on Requester / Waiting on Vendor / Reopened) requires horizontal scroll. Empty columns ("Triaged 0", "Waiting on Vendor 0") consume the same width as full columns. Either:
- Collapse empty columns to a thin "tray" with the count, or
- Reduce the column model: New / Triaged / Active / Waiting / Reopened (5 columns) — pair "Assigned" + "In Progress" into "Active", combine the two Waiting reasons into "Waiting" with a sub-badge.
This is downstream of the broader status-taxonomy issue (see 3.3): two facets in one field.

**6.2 SLA badge color/semantics conflate two facets.** "No SLA" rendered in green reads as "good" but actually means "no policy attached" — that's a routing gap, not a healthy ticket. Separate the badges:
- *SLA status:* On track (green) / At risk (amber) / Breached (red) / Paused (gray-amber)
- *Policy state:* shown only when missing, with a yellow caution icon ("Missing SLA policy")

**6.3 Card density vs column width.** ~270px cards carry ~9 pieces of metadata. Category and Channel chips are visually indistinguishable (same shape, same gray). Subject truncates mid-phrase ("Medicaid pending claim …") with no hover/expand. Reduce visual noise: drop one of category/channel into a single-letter icon, give subject room to wrap to 2 lines.

**6.4 No swimlanes / row grouping.** Kanban often benefits from rows (e.g. by Team or Priority) crossed with columns by Status. Currently it's flat.

**6.5 ~~Three-dot card menu has no visible affordance hint.~~ — RETRACT.** Verified: menu contains **Assign to / Edit priority / Move to / Transfer / View details** — full triage verb set, well chosen.

**6.6 No "add ticket" affordance per column.** Standard kanban offers "+ Add" at the column foot for adding a card directly in that column's state.

**6.7 No keyboard navigation for cards.** Triage is a high-throughput activity; J/K for next/prev card, arrow keys to move card between columns would speed it up significantly.

**6.8 Drag-and-drop — verified, two sub-findings.**
- [GOOD] **Backwards lifecycle transitions blocked** with a clear toast ("Cannot move from Assigned to Triaged"). Solid guardrail.
- [GOOD] **Forward transitions persist correctly** server-side (count Assigned 4 → 3, In Progress 2 → 3 after reload).

## 11. Cross-cutting findings

After 10 pages and the full Admin section, six themes show up everywhere.

### Theme 1 — Status taxonomy mixes two facets

The 9-status model (`New / Triaged / Assigned / In Progress / Waiting on Requester / Waiting on Vendor / Resolved / Closed / Reopened`) blends lifecycle states with **waiting reasons** with **lifecycle markers**. It bleeds into the UI in three places:

- All Tickets: "Status: Assigned" is redundant when the next column is the assignee (§3.4).
- Triage Board: 7 columns is too many; empty columns ("Triaged 0", "Waiting on Vendor 0") consume full width (§6.1).
- Status casing diverges across views: `Waiting On Requester` vs `Waiting on Requester` vs `WAITING_ON_REQUESTER` (§4.5).

**Fix:** Status = 5–6 lifecycle states only. Waiting Reason = separate field, surfaced as sub-badge or dropdown. Reopened = boolean flag/counter, not a status. One canonical casing.

### Theme 2 — Enum strings leak into the UI

Raw DB values appear in user-visible text across multiple surfaces:
- `IN_PROGRESS` / `REOPENED` in search results (§1.I-j)
- `add internal_note` (snake_case) in Automation rule THEN clause (§10.D)
- `INCIDENT` / `ASSIGNED → IN_PROGRESS` in Audit Logs (§10.F)
- `[Seed]` prefix everywhere (dev mode — pre-prod cleanup, not a bug)

**Fix:** single enum-to-label mapping layer; one canonical place that translates DB values to UI strings.

### Theme 3 — UUIDs in user-facing URLs and labels

- Ticket detail URL: `/tickets/7fe5d219-26da-4722-928a-00264943563c` (when ticket has `IS_20260430_010`) (§4.3).
- Teams sidebar links: `?teamIds=173e2c3a-af85-4a64-98f4-45a5c58a5d5b` (§9.11).
- Routing rule THEN clause: `Assign Team: b4973112-…` (§10.C).
- Audit Logs detail: `Frontemail: ba2061d1-…` (§10.F).

**Fix:** Use slugs/human IDs for URLs and team references; reserve UUIDs for internal joins.

### Theme 4 — KPI duplication across pages, with no clear ownership

Dashboard, Manager Views, and (when working) Reports overlap on ~70% of metrics (open tickets, resolved, SLA compliance). Currently each page tells its own version, sometimes inconsistently (Dashboard "Top Performer" inverted vs Manager Views Performance tab — §7.6).

**Fix:** Decide ownership.
- Dashboard = *personal* (assigned to me, mentions, my SLA risk).
- Manager Views = *strategic* (cross-team, by team, performance).
- Reports = *analyst* (configurable, exportable, full filter set).
Strip overlapping metrics from whichever page doesn't own each.

### Theme 5 — Naming / URL drift between sidebar, route, and page header

Across 16+ surfaces, sidebar entries / URLs / page headers don't agree:
- Sidebar "My Tickets" / URL `/tickets?scope=created` / no page title (§5)
- Sidebar "Reports" / URL `/reports` (also `/sla-settings`, `/routing`, no `/admin/` prefix) (§10.A)
- Sidebar "Audit Logs" / URL `/audit-log` / page "Audit Logs" (singular URL, plural everywhere else)
- Sidebar "Team" / page "Team Directory" / dropdown "Select **department**" (§9.1, §9.2)
- AI Submit page header says "How can we help?" but heading should be "AI Submit" (§2.1)

**Fix:** Canonical name per concept; sidebar, URL, page header, breadcrumbs all use it.

### Theme 6 — Loading and error states are inconsistent

- Dashboard renders "0" for KPIs and empty charts during fetch — no skeletons (§1.I-a).
- Reports renders "0" everywhere when 8 API calls 401 — no error banner (§8.1).
- SLA Overview shows "0% met (0/0)" — no small-sample guardrail (§10.B).
- Triage Board has proper empty states ("No tickets"); some KPI cards do not.
- Audit Logs has good pagination empty states.

**Fix:** Three states everywhere — loading (skeleton), empty (helpful copy + next action), error (banner + retry). Never fall back to "0" silently.

### Top 10 fixes ranked by ROI

If I could only ship 10 things:

1. **URL sync on master-detail row click** (§3.1) — biggest leverage; unblocks browser-native nav across the queue UI.
2. **Make Dashboard KPI cards drillable** (§1.I-b) — turns the dashboard from a poster into a console.
3. **Fix "Top Performer" inversion** (§1.10, §7.6) — data trust problem on the most visible page.
4. **Split Status into Status + Waiting Reason facets** (Theme 1) — fixes Triage column sprawl + All Tickets redundancy in one change.
5. **Single enum-to-label mapping layer** (Theme 2) — kills `IN_PROGRESS` / `snake_case` leaks site-wide.
6. **Use human IDs (not UUIDs) in shareable URLs** (Theme 3) — better Slack/email recognizability.
7. **Skeleton loaders + error banners replacing silent zeros** (Theme 6) — eliminates "system looks broken when it's just loading."
8. **Make ticket detail's Priority and Category editable** (§4.1) — common triage action currently blocked.
9. **Wire time range on Dashboard so all KPIs respect it** (§1.I-c) — currently only Transfers responds; trust gap.
10. **Re-architect KPI ownership across Dashboard / Manager Views / Reports** (Theme 4) — eliminates 70% duplication and inconsistency.
