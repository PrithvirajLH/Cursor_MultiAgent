### New API routes

All four sit **behind Easy Auth, which is correct**. **Do not add an Easy Auth
exclusion for any of them** — the only excluded paths remain
`/api/tickets/inbound-email` and `/api/tickets/intake`.

`OwnerGuard` — OWNER only (card 1.21):

```
GET  /api/operations
POST /api/operations/jobs/:key/run     key = sla-breach | retention | automation-scheduler
```

Card 1.13 — the ticket export is open to **any authenticated user** and relies on
`buildTicketAccessFilter` to scope the rows (a requester gets only their own).
The report export is `LeadOrAdminGuard` (OWNER, TEAM_ADMIN, LEAD), so an AGENT
gets 403:

```
GET  /api/tickets/export.csv                 authenticated; access filter scopes it
GET  /api/reports/:report/export.csv         LeadOrAdminGuard
```

Cards 1.22, 1.26 and 1.27 add **no routes**.

### Two new environment variables — leave both unset

Card 1.22 reads `EMAIL_ALLOWED_DOMAINS` (defaults to `csnhc.com`) and
`EMAIL_TEST_RECIPIENTS` (empty means pilot mode off). Both are documented in
`apps/api/.env.example`. **Set neither in this deploy.** They only matter once
card 1.23 switches sending on, and production still has no SMTP host.

## 4. Deploy

Follow `docs/DEPLOYMENT.md`. The short version, for the avoidance of doubt:

- **`create-deploy-zip.ps1` then `deploy-to-azure.ps1`** (Kudu zipdeploy).
- **Never push to the `azure` git remote.** Oryx rebuilds and breaks the flat
  `wwwroot` layout.
- `deploy-to-azure.ps1` **cannot** deploy the current package on its own — read
  the runbook, do not improvise.
- **Kill stray node processes before building**, or the Prisma query engine stays
  held and the build dies with `EPERM`. The planner ran dev servers on **3077**
  and **5173** today and stopped both. **A service on port 3000 is the LMS, not
  this app — leave it alone.**
- Two gitignored log files (`int-full.txt`, `it-sla.txt`) may be sitting at the
  repo root. Harmless, but clear them so they cannot reach the package.

No `prisma migrate deploy` step. There is nothing to apply.
