## 4. Decisions and assumptions

1. **Two new endpoints, both streamed:**
   - `GET /api/tickets/export.csv` — accepts `ListTicketsDto`, guarded like `GET /api/tickets` (any authenticated user; the access filter does the rest).
   - `GET /api/reports/:report/export.csv` — `report` is an `@IsIn` list of the **table-shaped** reports only (see §4.4). `AdminGuard`, same as the rest of the controller.
2. **Route ordering matters.** `@Get('export.csv')` must be declared **before** `@Get(':id')` in `tickets.controller.ts`, or `export.csv` is swallowed as a ticket id. Put it next to the other collection routes near the top.
3. **Cap at 50,000 rows.** Beyond that, stop and append a final line `# truncated at 50000 rows — narrow your filters`. A silent truncation is a lie; an error after a 40-second download is worse.
4. **Report allow-list** (the ones that are genuinely tabular): `team-summary`, `agent-performance`, `agent-workload`, `sla-breaches`, `tickets-by-status`, `tickets-by-priority`, `tickets-by-category`, `tickets-by-age`, `channel-breakdown`, `reopen-rate`, `transfers`, `resolution-time`, `sla-compliance`, `sla-compliance-by-priority`, `sla-compliance-by-team`, `csat-trend`, `csat-drivers`, `csat-low-tags`, `ticket-volume`. Anything else → 400 listing the valid names. **Excluded on purpose:** `summary`, `ai-accuracy`, `tag-analytics` — nested shapes that do not flatten to one table.
5. **Ticket columns**, in this order: `Ticket`, `Subject`, `Status`, `Priority`, `Department`, `Assignee`, `Requester`, `Requester email`, `Category`, `Channel`, `Tags`, `Created`, `Updated`, `Resolved`, `Closed`, `Close reason`, `First response due`, `Resolution due`, `SLA state`. Dates as **ISO 8601 UTC** (`2026-08-30T14:22:31Z`) — unambiguous, and Excel parses it. Tags joined with `; `.
6. **The fake share link goes.** Delete `shareLink`, its `useMemo`, the read-only input and its copy button. It advertises `https://app.helpdesk.local/...`, a domain that does not exist — it has been in the product since February and was flagged in the February quality report as FE-09. Replace that half of the panel with one honest line: "Exports download to your computer. Anyone you send the file to can read it — it contains requester names and email addresses."
7. **Filename carries the scope**: `tickets-2026-08-30.csv`, `report-team-summary-2026-08-30.csv`.
8. **CSV escaping:** wrap a value in double quotes when it contains `,`, `"`, `\n` or `\r`; double any embedded `"`. Prefix a leading `=`, `+`, `-` or `@` with `'` — a subject like `=cmd|...` is a spreadsheet-injection vector and this file is opened in Excel by definition.

## 7. Security considerations

- **The export must never widen access.** It reuses `buildTicketAccessFilter` and `scopeReportQuery` — do not add a bypass, a team override, or an `includeDeleted` flag. Integration cases 3 and 4 are the proof.
- **Spreadsheet injection** is a real risk here because the file is opened in Excel by definition: a subject beginning `=`, `+`, `-` or `@` must be prefixed with `'`. Case 5 covers it.
- The file contains requester names and email addresses. Say so in the UI (§4.6) — the person clicking Export is the one who decides where the file goes.
- The fake share link is being removed partly because it is dead and partly because a link that looks like a sharing feature but is not invites someone to paste it somewhere expecting access control.

## 8. Acceptance criteria

1. Filter the ticket list, click Export, open the file: the same rows, the same order, sensible columns, dates readable in Excel.
2. A requester's export contains only their own tickets; an agent's contains only what they can see.

4. No `helpdesk.local` string remains anywhere in the web app (`grep -r "helpdesk.local" apps/web/src` → nothing).
