## 4. Deploy — migration first

Follow `docs/DEPLOYMENT.md`. Read **Gotcha 0** before starting: writing to Azure
needs a Conditional Access token and the failure does not say so.

**Additive schema goes first on purpose** (`DEPLOYMENT.md`, "Why migrate first"):
old code keeps working against the new schema, so the window between the
migration and the app is safe. Ship the app first and it queries a column that
does not exist yet.

### Step 1 — Record where production is, before changing anything

```bash
az webapp config appsettings list -g csnhc-ai -n TicketTicket \
  --query "[?name=='DEPLOYED_COMMIT_SHA'].value | [0]" -o tsv

PROD=$(az webapp config appsettings list -g csnhc-ai -n TicketTicket \
  --query "[?name=='DIRECT_URL'].value | [0]" -o tsv)
cd apps/api
DATABASE_URL="$PROD" DIRECT_URL="$PROD" npx prisma migrate status   # KEEP THIS OUTPUT
```

**Save both.** They are the rollback reference and the answer to what the morning
deploy did.

### Step 2 — Apply migration 53

```bash
DATABASE_URL="$PROD" DIRECT_URL="$PROD" npx prisma migrate deploy
DATABASE_URL="$PROD" DIRECT_URL="$PROD" npx prisma migrate status   # expect 53, up to date
```

- **`DIRECT_URL` is port 5432.** The 6543 pooler **cannot run migrations at all** —
  never point `migrate deploy` at it (`DEPLOYMENT.md` §6).
- If `migrate status` reports anything pending **other than 53**, **stop and
  report** — that means the morning deploy left the schema somewhere unexpected.

### Step 3 — Build and push the app

1. **Kill stray node processes.** Use the repo-scoped filter in
   `repo-landmines.md`, and note the 2026-09-02 addition: **that filter misses a
   dev server started with a relative path**, so check the listening ports too. A
   broad `node.exe` filter took down an unrelated dev server.
2. **Build** with `create-deploy-zip.ps1`. **Rebuild is required.**
3. **Push:**

   ```bash
   az webapp deploy -g csnhc-ai -n TicketTicket --type zip --async true --src-path <zip>
   ```

   **Do NOT run `deploy-to-azure.ps1`** — `docs/DEPLOYMENT.md:38` forbids it; the
   package is ~170 MB and its Kudu zipdeploy 502s, which tells you nothing.
   **Never push to the `azure` git remote.**
