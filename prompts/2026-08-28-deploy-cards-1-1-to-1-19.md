### New background behaviour to be aware of

The automation scheduler (card 1.3) starts **enabled by default** and runs every 5 minutes. It is harmless: it only looks at rules whose trigger is time-based, and **production has no such rules** until an admin creates one. Expect one log line at start-up (`Automation scheduler enabled (every 300000 ms)`) and quiet ticks after that. To keep it off entirely, set `AUTOMATION_SCHEDULER_ENABLED=false` — not recommended, since it makes card 1.3 inert.

The retention job (card 0.8, already deployed) remains **off** — unchanged by this release.

## 7. If something goes wrong

- **Migration fails partway:** stop. Report the `migrate status` from §3 step 1 (the rollback reference) and the error. Both migrations are additive, so the old code keeps working against the new schema — there is no rush to undo anything.
- **Deploy reports 502:** that means "you don't know", not "it failed". Check `az webapp log deployment list` before doing anything else.
- **Every URL returns 401:** normal — that is Easy Auth. Verify through Kudu (§4) and a signed-in tab.
- **Rollback:** redeploy the previous commit `d1d57bc` (rebuild from that SHA, redeploy). The two new columns/values stay; old code ignores them.
